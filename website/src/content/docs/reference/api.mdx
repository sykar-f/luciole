The framework keeps no business state. It holds no unsaved text, no pending operation and no
retry policy. It reports what happened to each request, and the app decides what to do.

## Use `@luciole-sh/core/client` in Client Components

Import every name of this section from `@luciole-sh/core/client`, in Client Components only.

Each entry gives its signature or props, its defaults, the errors it raises and an excerpt of
code that uses it. The excerpts come from the examples and the tests, which the project
type-checks. Where no compiled code uses an entry, a short fragment stands in, labelled as one.

luciole's own hooks read the running app, so they work only inside its tree. Outside it, they
throw `Missing terminal shell`. The field hooks and components throw a message that names the
field.

### Navigate between pages

### Reach the app and its connection

| Export                              | Contract                                                                                                                              |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `useApplication()`                  | Returns the running `Application` (members below).                                                                                    |
| `useConnection()`                   | Returns `{ status, error, buildError, activity, refresh }` (members below), and renders again when one of them changes.               |
| `useInvalidation(listener)`         | Calls `listener(paths, tags)` at every invalidation, from the Server or the Client. Both arguments are `readonly string[]`.           |
| `useLive(source, args, { limit }?)` | Returns `{ items, done, error }` of a generator Server Function. `limit` bounds `items`. Default: `1000` values.                      |
| `TransportError`                    | A failed request: `new TransportError(message, outcome?)`. Its `outcome` is an `Outcome`. Default: `unknown`.                         |
| `BuildMismatch`                     | A `TransportError` with the outcome `rejected`. The Server answered `409`: it runs another build.                                     |
| `AuthenticationRequired`            | A `TransportError` with the outcome `rejected`. The Server answered `401`. `loginPath` is the page to sign in on, if the app has one. |
| `Outcome`                           | `"not-sent" \| "rejected" \| "unknown"`: what a failed request says about its effect on the Server (below).                           |

`Outcome` tells you whether retrying is safe
([Server Functions](/docs/concepts/server-functions/#when-a-call-fails)):

| Outcome    | When                                                                                     | Did app code run? |
| ---------- | ---------------------------------------------------------------------------------------- | ----------------- |
| `not-sent` | The connection was refused or never opened, or the request was cancelled before it left. | No                |
| `rejected` | The Server answered with a `4xx` status, `401` and `409` included.                       | No                |
| `unknown`  | The answer timed out, was lost or was cut, or the Server answered with a `5xx` status.   | Maybe             |

`useLive(source, args, { limit }?)` opens its request on mount, and again when `args` change.
It compares `args` as JSON. Unmounting cancels the request and stops the Server's generator.
Nothing reconnects by itself: `error` says why the stream stopped, and `done` turns `true`.

`useApplication()` returns an object with these members:

| Member                             | Contract                                                                                                                                          |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `setToken(token?)`                 | Replaces the token for later requests and reloads the current routes. It drops cached pages, and named fields after the first sign-in.            |
| `refresh()`                        | Reloads the current routes and returns a promise. On a failure, the page on screen stays.                                                         |
| `invalidate(paths?)`               | Reloads the routes under `paths` and calls the `useInvalidation` listeners. Default: `["/"]`, every route.                                        |
| `cancel()`                         | Goes back to the last loaded page while a navigation is pending, without a request.                                                               |
| `withSignal(signal, call, cause?)` | Runs `call` and returns its result. Aborting `signal` cancels the Server Function that `call` starts, and its stream. `cause` labels its request. |
| `onEvent(listener)`                | Calls `listener` with each event ([events below](#observe-requests-and-navigations)). Returns the function that unsubscribes.                     |
| `dispose()`                        | Closes a pane's app: its requests and streams stop, and its listeners are dropped. A Client with one app never needs it.                          |
| `status`                           | The last known state of the connection (values below).                                                                                            |
| `error`                            | Why the current route could not reload. The next success clears it.                                                                               |

The first sign-in of a Client keeps the named fields, so text restored after a crash survives
it. Later calls to `setToken` clear them.

`useConnection()` returns an object with these members:

| Member       | Contract                                                                                                 |
| ------------ | -------------------------------------------------------------------------------------------------------- |
| `status`     | `Connecting`, `Connected`, `Disconnected`, `Incompatible build` or `Authentication required`.            |
| `error`      | The same value as `useApplication().error`.                                                              |
| `buildError` | In development, the last build failure. It stays until the next build succeeds.                          |
| `activity`   | `connect` before the first page, `navigate` during a navigation, `refresh` during a reload, else `idle`. |
| `refresh`    | The same function as `useApplication().refresh`.                                                         |

### Restore fields and bind keys

Name a field to keep its text for the current history entry: the text comes back after going
back to the entry, a crash or a rebuild
([session restore](/docs/concepts/session-restore/)). A name `group/field` joins the group
`group`. Without a name, each component is OpenTUI's own.

| Export                                    | Contract                                                                                                                             |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `<Input name? value onInput />`           | OpenTUI's `input`, controlled. Its props are `FieldInputProps`: OpenTUI's `input` props, with the three below.                       |
| `<Textarea name? value onChange />`       | OpenTUI's `textarea`, controlled. Its props are `FieldTextareaProps`: OpenTUI's `textarea` props, with the three below and `ref`.    |
| `<ScrollBox name? …>`                     | OpenTUI's `scrollbox`. Its props are `FieldScrollBoxProps`: OpenTUI's `scrollbox` props and `name`, which keeps the scroll position. |
| `useRestoredFields(group)`                | Returns the `RestoredFields` of the `group/…` fields of the current history entry (below).                                           |
| `useRestoredField(name, value, onChange)` | Makes a field of your own restorable. Returns the function to call with every text typed.                                            |
| `useRestoredFocus(names)`                 | Returns `[focus, setFocus]`: which of `names` has the focus, kept per history entry. Default: the first name.                        |

The props that `<Input>` and `<Textarea>` add:

| Prop                                               | Type                      | Default  | Contract                                                                      |
| -------------------------------------------------- | ------------------------- | -------- | ----------------------------------------------------------------------------- |
| `name`                                             | `string`                  | none     | Keeps the text per history entry.                                             |
| `value`                                            | `string`                  | required | The text shown. A new value replaces the text of a `<Textarea>`, cursor last. |
| `onInput` on `<Input>`, `onChange` on `<Textarea>` | `(value: string) => void` | none     | Called with each change typed, and once with the restored text on mount.      |

`<ScrollBox name>` applies its kept position once the content is tall enough. It tries every
50 ms, for 1,500 ms after mounting, and scrolling by the user wins.

`RestoredFields` has two members:

- `submit(action, { failed? }?)` forgets the group's kept text, on disk too, then runs
  `action` and returns its result. The text is kept again when `action` throws a
  `TransportError` whose outcome is `not-sent` or `rejected`, or when `failed(result)`
  returns `true`. Text typed in the meantime wins.
- `clear()` forgets the group's kept text. The fields keep their value.

A named field outside the app's tree throws an error that names it:

| Call                                                  | Error                                                       |
| ----------------------------------------------------- | ----------------------------------------------------------- |
| `<Input name>`, `<Textarea name>`, `useRestoredField` | `Field "<name>" is outside the terminal shell`              |
| `<ScrollBox name>`                                    | `Scroll box "<name>" is outside the terminal shell`         |
| `useRestoredFields(group)`                            | `Fields "<group>" are outside the terminal shell`           |
| `useRestoredFocus(names)`                             | `The focus of "<first name>" is outside the terminal shell` |

### Show other apps, terminals and Markdown

A host shows other luciole apps and local programs in panes
([terminals and panes](/docs/guides/terminals-and-panes/)).

| Export                                                          | Contract                                                                                |
| --------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `<Embed app name active prefix? />`                             | Another luciole app in a pane. Its props are `EmbedProps`.                              |
| `openApplication({ bundle, url, instance? })`                   | Loads the app that `<Embed app>` takes. Its options are `OpenApplicationOptions`.       |
| `<Terminal command active prefix? cwd? env? onExit? />`         | A local program on a PTY, drawn in the tree. Its props are `TerminalProps`.             |
| `<TerminalView program label spawn active prefix? onExit? />`   | The same widget, with the host starting the program. Its props are `TerminalViewProps`. |
| `<Markdown content streaming syntaxStyle onLink? imageBase? />` | Markdown rendered by blocks. Its props are `MarkdownProps`.                             |
| `markdownStyle(palette)`                                        | Returns a complete `SyntaxStyle` from a `MarkdownPalette` of 12 colors.                 |

#### Embed another app

`openApplication(options)` returns a promise of an `Application`, connected to its Server.
Disposing that `Application` closes the connection.

| Option of `OpenApplicationOptions` | Type             | Default          | Contract                                                                     |
| ---------------------------------- | ---------------- | ---------------- | ---------------------------------------------------------------------------- |
| `bundle`                           | `string`         | required         | The app bundle the build writes: `<app>/.luciole/app`.                       |
| `url`                              | `string`         | required         | Its Server: `http(s)://…`, `unix:/path` or `ssh://…`.                        |
| `instance`                         | `string`         | a new random key | The pane's key, which matches `[a-z0-9-]{1,32}`.                             |
| `publisher`                        | `PublisherCheck` | none             | What the bundle's signature must satisfy (below).                            |
| any other                          |                  |                  | The options of `createApplication`, but `fetch` and the ones the build sets. |

`PublisherCheck` is `{ required?, trust? }`:

- `required: true` refuses an unsigned bundle. Default: `false`.
- `trust(fingerprint, manifest)` runs before a signed bundle runs. It receives the
  fingerprint of the key that signed it. Throw to refuse the bundle.

`openApplication` rejects when:

- the instance key does not match `[a-z0-9-]{1,32}`
- the directory holds no bundle: `<directory> has no application bundle: build the application with luciole build …`
- `required` is set and the bundle is unsigned: `<directory>: the manifest is not signed by its publisher`
- `trust` throws
- the bundle was built for another runtime: `<directory>: built for runtime ABI …`
- the Server cannot be reached

| Prop of `EmbedProps`          | Type                                       | Default  | Contract                                                                              |
| ----------------------------- | ------------------------------------------ | -------- | ------------------------------------------------------------------------------------- |
| `app`                         | `Application`                              | required | The pane's app, from `openApplication`.                                               |
| `name`                        | `string`                                   | required | Names the pane. Its box has the ID `embed-<name>`.                                    |
| `active`                      | `boolean`                                  | required | Whether the pane has the keys. The host decides.                                      |
| `prefix`                      | `string`                                   | none     | The host's key, such as `"ctrl+o"`. It and the sequence it starts stay with the host. |
| `flexGrow`, `width`, `height` | `number`, or `` `${number}%` `` for a size | none     | The pane's box.                                                                       |

An error in the pane replaces the pane with `<name> crashed: <message>`. The rest of the host
keeps running. An inactive pane holds no focus: the element that had it gets it back when the
pane becomes active again.

#### Run a program in a pane

| Prop of `TerminalProps`             | Type                                  | Default       | Contract                                                                                          |
| ----------------------------------- | ------------------------------------- | ------------- | ------------------------------------------------------------------------------------------------- |
| `command`                           | `readonly string[]`                   | required      | The program and its arguments. It starts at the first layout, at the pane's size.                 |
| `active`                            | `boolean`                             | required      | Whether the program has the keys. It then gets every key but `prefix`, Ctrl+C included.           |
| `prefix`                            | `string`                              | none          | The host's key. Without it, only `active` or a click gives the keys back.                         |
| `cwd`                               | `string`                              | the Client's  | The program's directory.                                                                          |
| `env`                               | `Record<string, string \| undefined>` | none          | Added to the Client's environment, after `TERM=xterm-256color` and `COLORTERM=truecolor`.         |
| `onExit`                            | `(code: number \| null) => void`      | none          | The program ended. `null` means a signal killed it, or it could not start. Its last screen stays. |
| `scrollback`                        | `number`                              | `10000` lines | The lines kept above the screen.                                                                  |
| `id`, `flexGrow`, `width`, `height` |                                       | none          | The pane's box.                                                                                   |

`TerminalViewProps` takes the same props, except `command`, `cwd` and `env`, and adds three:

| Prop      | Type          | Contract                                                              |
| --------- | ------------- | --------------------------------------------------------------------- |
| `program` | `string`      | Identifies the program. A new value replaces the running program.     |
| `spawn`   | `(io) => Pty` | Starts the program. `io` holds `cols`, `rows`, `onData` and `onExit`. |
| `label`   | `string`      | The program's name in an error line.                                  |

A program that cannot start raises nothing in your code. The pane prints
`<label>: <message>`, then `onExit(null)` runs. For `<Terminal>`, the label is the command.
An empty `command` prints `A terminal needs a command`. Unmounting the pane, or changing
`command`, sends the program a hangup (`SIGHUP`).

#### Render Markdown that streams

`<Markdown>` shows text that arrives in pieces, typically a model's answer, without flicker:

- Finished blocks render once.
- The last block is closed ahead of time, so `**bold` shows bold.
- Text is styled without Tree-sitter, so the streaming and final renders match.
- Code is coloured once its fence closes, and `diff` blocks line by line from the start.
- A click on a link calls `onLink(url)`.
- Images are drawn with kitty, sixel or half blocks.

| Prop of `MarkdownProps` | Type                    | Default  | Contract                                                                                        |
| ----------------------- | ----------------------- | -------- | ----------------------------------------------------------------------------------------------- |
| `content`               | `string`                | required | The Markdown to show.                                                                           |
| `streaming`             | `boolean`               | required | Whether `content` is still being written. While `true`, the last block is closed ahead of time. |
| `syntaxStyle`           | `SyntaxStyle`           | required | The colors, typically from `markdownStyle`.                                                     |
| `onLink`                | `(url: string) => void` | none     | Called when a link is clicked. Without it, a click on a link does nothing.                      |
| `imageBase`             | `string`                | none     | The directory or URL that relative image paths start from. Without it, they show as text.       |

### Ask the host for a capability

`host` asks whoever hosts the app for what the app cannot do by itself. Its type is `Host`.

| Export                          | Contract                                                                                  | Capability        |
| ------------------------------- | ----------------------------------------------------------------------------------------- | ----------------- |
| `host.clipboard.read()`         | Resolves with the clipboard's text.                                                       | `clipboard.read`  |
| `host.clipboard.write(text)`    | Writes `text`, at most 1,048,576 characters, to the clipboard.                            | `clipboard.write` |
| `host.notify({ title, body? })` | Shows a system notification. `title` holds at most 256 characters, `body` 4,096.          | `notify`          |
| `host.openUrl(url)`             | Opens `url` in the browser. It takes `http` and `https` URLs of at most 2,048 characters. | `open-url`        |
| `host.secret(name)`             | Resolves with the origin's keychain entry `name`, or `undefined` when it is absent.       | `secrets`         |
| `host.tabs.post(message)`       | Sends a JSON value, at most 65,536 characters once serialized, to the app's other tabs.   | `tabs.message`    |
| `host.tabs.onMessage(fn)`       | Calls `fn(message, from)` for each message from another tab. Returns the unsubscribe.     | `tabs.message`    |
| `host.input.onGlobalKey(fn)`    | Calls `fn(key)` for each global key. Returns the unsubscribe.                             | `input.global`    |

A secret's `name` matches `[\w.-]{1,64}`. A standalone Client has no other tab, so
`host.tabs.post` reaches nobody there.

| Export                  | Contract                                                                                                |
| ----------------------- | ------------------------------------------------------------------------------------------------------- |
| `CapabilityDenied`      | The error each `host` call rejects with when the host refuses. Its `capability` names what was refused. |
| `useHostMessage(fn)`    | `host.tabs.onMessage(fn)` while the component is mounted.                                               |
| `useGlobalKey(key, fn)` | Calls `fn` on the global key `key` while the component is mounted.                                      |
| `useCapability(name)`   | Returns the capability's state, a `CapabilityState`. The component renders again when it changes.       |
| `CapabilityState`       | `granted`, `denied` by the user, or `prompt`: the host asks the user at the first request.              |
| `GlobalKey`             | `{ name, sequence, ctrl, meta, shift }`: a key typed while another pane has the focus.                  |

`useGlobalKey` takes a key such as `"ctrl+s"` or `"f5"`. Its modifiers are `ctrl`, `shift` and
`meta`, and `alt` counts as `meta`. A key matches when its name and all of its modifiers are the
same, whatever their case.

| ------------ | ------------------------------------------- | ------------------------------------------------------ |
| `request`    | A request leaves.                           | `callId`, `kind`, `target`, `cause`                    |
| `response`   | The response's status arrives.              | `callId`, `kind`, `target`, `status`, `ms`             |
| `chunk`      | A chunk of the body arrives.                | `callId`, `kind`, `target`, `bytes`                    |
| `end`        | The body ends or is cancelled.              | `callId`, `kind`, `target`, `ms`, `bytes`, `cancelled` |

| `navigation` | A navigation resolves.                      | `path`                                                 |
| `invalidate` | The Server or the Client declares a change. | `paths`, `origin`, and `tags` when cache tags changed  |
| `loader`     | A page loader starts or ends.               | `phase`, `routeId`, `href`, `cause`, `source`          |
| `failure`    | A page fails to load or render.             | `path`, `message`                                      |

- The first five are the transport's events, of the type `TransportEvent`. They also carry
  `id`, which numbers the requests of this Client.
- `callId` is the ID the Server reads with `getCallId()`.
- `kind` is `render` for a page and `action` for a Server Function.
- `ms` counts milliseconds since the request left, and `bytes` counts the body's bytes.
- `cause` is a `RequestCause`: `navigation`, `preload`, `refresh`, `invalidation`,
  `action`, `live` or `unknown`.
- `origin` is `server` or `client`.
- A `loader` that ends also carries `ms` and `result`: `ok`, `error` or `aborted`. Its
  `source` is `router-cache` when the router showed the page from its cache, without a
  request.
- `notFound()` does not emit a `failure`.
- Listeners run on the hot path. Keep them light, and never let them throw.

### Cache Server reads

These exports age, label and store the results of `"use cache"` functions.
[Caching Server reads](/docs/concepts/cache/) explains when a call reads an entry.

| Export                               | Contract                                                                                                                                                                                            |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cacheLife(life)`                    | Sets how long the running result stays fresh. `life` is a `CacheProfile` or `{ revalidate?, expire? }`, in seconds.                                                                                 |
| `cacheTag(...tags)`                  | Labels the running result. A tag holds 1 to 256 visible ASCII characters, without commas or spaces. A result holds at most 64 tags.                                                                 |
| `invalidate({ tag })`                | Drops the results labelled `tag`, from any Server code. Returns a `Promise<void>` that resolves once they are gone.                                                                                 |
| `CacheProfile`                       | `"default" \| "seconds" \| "minutes" \| "hours" \| "days" \| "weeks" \| "max"`. The [profiles table](/docs/concepts/cache/#label-and-age-a-result-with-cachetag-and-cachelife) gives their seconds. |
| `memoryCache({ maxEntries? })`       | The default store, in this process only. The least recently used entry leaves first. Default: `1000` entries.                                                                                       |
| `sqliteCache({ path, maxEntries? })` | A store in the SQLite file at `path`, created if missing. It survives restarts, and the oldest entries leave first. Default: `10000` entries.                                                       |
| `CacheHandler`                       | The type of a store: `get(key)`, `set(key, entry)` and `invalidateTags(tags)`. Each returns its value or a `Promise` of it.                                                                         |
| `CacheEntry`                         | `{ value, tags, createdAt, revalidate, expire }`. `value` is opaque text, `createdAt` is epoch milliseconds, the durations are seconds.                                                             |
| `CacheEvent`                         | `{ type: "cache", op, key, fn, tags, callId, ms, at }`, with `op` one of `hit`, `miss`, `stale`, `write` and `invalidate`.                                                                          |

A result whose function never calls `cacheLife` takes the `default` profile: 900 seconds,
and no expiry. A field that `{ revalidate?, expire? }` leaves out takes its `default` value
too. When `cacheLife` runs more than once, the shortest value of each field wins.

`invalidateTags(tags)` must remove the entries before it resolves, since the Client reads
again right after. Export the store from `server/cache.ts`, as
[Where entries live](/docs/concepts/cache/#where-entries-live) shows.

These calls throw with these messages:

| Call                                  | Message                                                              | When                                                                 |
| ------------------------------------- | -------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `cacheLife()`, `cacheTag()`           | `<call> is only available inside a "use cache" function`             | Called outside a cached function.                                    |
| `cacheLife(name)`                     | `Unknown cache profile: <name>`                                      | `name` is not a `CacheProfile`.                                      |
| `cacheLife({ revalidate?, expire? })` | `revalidate must not exceed expire`, in a `ZodError`                 | `revalidate` ends up above `expire`, as with `{ expire: 60 }` alone. |
| `cacheTag()`, `invalidate({ tag })`   | `tags are 1–256 visible ASCII characters, no comma`, in a `ZodError` | A tag breaks the rule above.                                         |
| `cacheTag()`                          | `At most 64 tags per cached result`                                  | The result holds more than 64 tags.                                  |

### Describe the app to the Server with `ServerConfig`

`luciole build` writes `.luciole/server/index.js`, which builds a `ServerConfig` and calls
`serve(config)`. You write one yourself only to run a Server without the build, as luciole's
tests do.

| Field         | Type                                                   | Contract                                                                                                   |
| ------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| `buildId`     | `string`                                               | The build's ID. A request whose `x-luciole-build` header differs gets a 409.                               |
| `manifest`    | `unknown`                                              | The Client References of the build, as `luciole build` writes them.                                        |
| `actions`     | `Map<string, { fn: ServerFunction; auth: RouteAuth }>` | The Server Functions, keyed by their ID, `path#name`. The Client sends it in `x-luciole-action`.           |
| `routes`      | `Map<string, ServerRoute>`                             | The pages, keyed by their route ID.                                                                        |
| `auth?`       | `AuthConfig`                                           | Who is signed in. `serve` reads it, and `createHandler` takes `options.auth` instead.                      |
| `instrument?` | `ServerInstrument`                                     | Receives each request event and each cache event. Default: none.                                           |
| `cache?`      | `CacheHandler`                                         | Where cached results live. Default: `memoryCache()`.                                                       |
| `appBundle?`  | `string`                                               | The directory of the application bundle, `.luciole/app`. When it exists, hosts can load the app from it.   |
| `web?`        | `string`                                               | The directory of the web runtime, `.luciole/web`. `serve` serves it to the origin in `LUCIOLE_WEB_ORIGIN`. |

The types of its fields:

| Type               | Definition                                      | Contract                                                                                                    |
| ------------------ | ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `RouteAuth`        | `"public" \| "required"`                        | A `required` page or Server Function answers 401 to a request without a sign-in session.                    |
| `ServerFunction`   | `(...args: unknown[]) => unknown`               | Its arguments arrive decoded but unchecked: validate them first. An async iterable it returns streams live. |
| `ServerRoute`      | `{ component, auth, url, params }`              | `component` receives `{ params, searchParams }`, both `Record<string, string>`.                             |
| `ServerInstrument` | `{ onEvent(event: ServerEvent \| CacheEvent) }` | Called synchronously on the request's path. Keep it cheap, and never throw from it.                         |

A `ServerRoute`'s `url` is the pattern with `$name` parameters. The Server uses it only to
check `unauthorizedPath`. A request must give exactly the names in `params`, each a non-empty
string. Its search holds at most 32 keys, each of 1 to 64 letters, digits, `_`, `.` or `-`. A
value holds 1,000 characters at most.

### Start a Server with `serve`

`serve(config: ServerConfig)` starts the Server on `Bun.serve` and returns Bun's `Server`. It
takes the rest from the [Server's environment](/docs/reference/environment/#configure-the-server):

- It listens on `LUCIOLE_SOCKET`, or else on `LUCIOLE_HOST` and `PORT`. Defaults:
  `127.0.0.1` and `3000`.
- Without `config.auth`, a request carrying `Authorization: Bearer <LUCIOLE_TOKEN>` is
  signed in as `LUCIOLE_USER`. When `LUCIOLE_TOKEN` is unset, every request is.
- A request body holds 1 MiB at most.
- A TCP connection idle for 30 seconds closes, but a live response keeps its connection. A
  socket has no idle timeout.
- Once it listens, it prints one line on stdout: `{"ready":true,"port":…,"pid":…,"buildId":…}`,
  with `socket` in place of `port`.
- It stops on SIGTERM and SIGINT. On a socket, the launcher also decides how long it lives.

`serve` throws before it listens, with these messages:

| Message                                                                                       | When                                                                       |
| --------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `Invalid Server environment: <details>`                                                       | A variable fails its check, such as a `PORT` that is not an integer.       |
| `Remote binding requires LUCIOLE_TOKEN or server/auth.ts and a TLS reverse proxy`             | `LUCIOLE_HOST` is not a loopback address, with no socket, token or `auth`. |
| `LUCIOLE_WEB_ORIGIN is set but this build has no web runtime: build with luciole build --web` | `LUCIOLE_WEB_ORIGIN` is set and `config.web` holds no web runtime.         |
| `<web> was built for runtime ABI <abi>, this Server has <abi>`                                | The web runtime comes from another version of luciole.                     |

It also throws the errors of `createHandler`, below.

### Observe requests with `instrument`

`instrument.onEvent(event)` receives two kinds of events:

- a `ServerEvent` for every `/render` and `/action`: `request`, `response`, `end` or `error`,
  with `callId`, `kind`, `target` and `at`
- each `CacheEvent` of the cache

| `ServerEvent` type | Extra fields               | When                                                                             |
| ------------------ | -------------------------- | -------------------------------------------------------------------------------- |
| `request`          | none                       | The request arrives.                                                             |
| `response`         | `status`, `ms`             | The handler returned its `Response`.                                             |
| `end`              | `ms`, `bytes`, `cancelled` | The body ended, or the Client went away. A live body ends with its generator.    |
| `error`            | `ms`, `message`            | The handler threw, in place of `response`, or the body failed while it streamed. |

`at` is epoch milliseconds, and `ms` counts from the request's arrival. `target` is the route
ID or the Server Function ID, as the request gave it. Without `instrument` or `devtools`, no
response is wrapped.

## Render display math with `@luciole-sh/core/math`

```ts
import { renderMath } from "@luciole-sh/core/math";

const png = await renderMath("e^{i\\pi} + 1 = 0", { display: true, color: "#e6e6e6", scale: 8 });
```

`renderMath(tex, { display, color, scale })` returns a `Promise<Uint8Array>`:

- a PNG of `tex` on a transparent background, in `color`
- at `scale` pixels per `ex`
- in display math when `display` is `true`, else inline math

It rejects TeX that MathJax cannot read.

Pass it to the `math` option of `@luciole-sh/markdown-editor` to draw display math in
terminals that draw pictures, as Notes does.

The entry is opt-in, like `grammars`. Its two optional peer dependencies, `mathjax-full` and
`@resvg/resvg-wasm`, weigh a few megabytes. Install them in your app. They load on the first
formula.

## Run a program on a PTY: `@luciole-sh/core/pty`

`spawnPty(options)` starts a program on a pseudo-terminal and returns a `Pty`. `<Terminal>`
draws what it writes. It runs on `Bun.Terminal`, with no native addon. It is POSIX only,
because Bun has no PTY on Windows.

```ts
import { spawnPty, type Pty, type PtyOptions } from "@luciole-sh/core/pty";
```

| `PtyOptions` field | Contract                                                                                   | Default        |
| ------------------ | ------------------------------------------------------------------------------------------ | -------------- |
| `command`          | The argv, or a function that receives the path of the PTY's device and returns the argv.   | required       |
| `cols`, `rows`     | The PTY's size, in cells.                                                                  | required       |
| `env?`             | Variables set over the environment, after `TERM=xterm-256color` and `COLORTERM=truecolor`. | none           |
| `environment?`     | `inherit` starts from this process's environment. `replace` starts from nothing but `env`. | `inherit`      |
| `cwd?`             | The program's directory.                                                                   | this process's |
| `ipc?`             | Opens Bun's JSON IPC channel to the program, and receives each message it sends.           | no channel     |
| `onData(bytes)`    | Receives what the program writes, to feed a terminal emulator.                             | required       |
| `onExit(code)`     | Called once the program ends, with its exit code, or `null` after a signal.                | required       |

A sandbox profile grants one device, so a confined program needs the device's path before it
starts. That is why `command` can be a function.

| `Pty` member         | Contract                                                                             |
| -------------------- | ------------------------------------------------------------------------------------ |
| `write(data)`        | Writes a string or bytes to the program's input. Ignored once the PTY is closed.     |
| `resize(cols, rows)` | Resizes the PTY. The kernel sends SIGWINCH to the foreground process group.          |
| `kill()`             | Sends SIGHUP, as a closed terminal window does. Ignored once the program has exited. |
| `send(message)`      | Sends a message over the IPC channel. Ignored without `ipc`, or after the exit.      |
| `pid`                | The program's process ID.                                                            |

How the program runs:

- It leads a terminal session of its own, whose controlling terminal is the PTY. <kbd>Ctrl+C</kbd> then
  reaches its foreground process group.
- On Linux, that needs `setsid` from util-linux or busybox on the `PATH`. Without it, the
  program runs without job control.
- When this process exits, each program still running receives SIGKILL on its process group,
  then its PTY closes.

`spawnPty` throws `A terminal needs a command` when the argv is empty. A `command` function
throws `The new PTY's device path could not be found` when the device cannot be found.

## Confine an app: `@luciole-sh/core/sandbox`

This entry gives a host outside the framework the `sandbox` mode: a Client that the OS
confines, drawn by `<TerminalView>`, with the capabilities the host mediates over IPC. It also
confines a Server. [Apps you did not write](/docs/guides/untrusted-apps/) explains the mode, and
the generic Client uses the same functions.

```ts
import {
  buildChild,
  openSandbox,
  sandboxAvailability,
  sandboxRuntime,
} from "@luciole-sh/core/sandbox";
```

### Find what confines a Client here

| Export                      | Contract                                                                                                                                |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `sandboxAvailability(env?)` | Returns an `Availability`, found once per process. `env` defaults to `process.env`.                                                     |
| `Availability`              | `{ mechanism, byDefault }`, or `{ mechanism: undefined, reason }` when nothing can confine a Client here.                               |
| `Mechanism`                 | `{ kind: "seatbelt" }` on macOS. On Linux, `{ kind, landlockAbi, launcher, bwrap? }`, with `kind` one of `userns`, `bwrap`, `landlock`. |
| `mechanismName(mechanism)`  | Returns the mechanism's label on the capabilities screen and the status line.                                                           |
| `sandboxRuntime()`          | Resolves with what a confined child must read to run: Bun, its libraries, luciole's sources and their packages. Found once.             |
| `buildChild()`              | Builds the confined Client's entry, and resolves with its path. Rejects with `The sandbox child did not build:` and Bun's logs.         |

The mechanisms, strongest first:

1. `seatbelt` on macOS: `sandbox-exec` and a generated profile.
2. `userns` on Linux: `luciole-sandbox` enters its own namespaces, then applies Landlock and
   seccomp.
3. `bwrap`: bubblewrap makes the namespaces when the system forbids `luciole-sandbox` to.
4. `landlock`: Landlock alone. It filters TCP by port, not by host, so `byDefault` is `false`.

`reason` says why nothing confines, such as `/usr/bin/sandbox-exec is missing`, `no sandbox on
win32`, or `<launcher> does not match its SHA256SUMS`. Two variables change the choice:
`LUCIOLE_SANDBOX_MECHANISM` and `LUCIOLE_SANDBOX_LAUNCHER`
([environment](/docs/reference/environment/)).

`mechanismName` returns `Seatbelt`, `Landlock + espaces de noms`, `bubblewrap + Landlock`,
`bubblewrap` or `Landlock seul`. These labels are in French, as the rest of the capabilities
screen is today.

### Open a confined Client

`openSandbox(origin, options)` resolves with a `Sandbox`. It connects to the Server, and prepares a
private scratch directory and the egress proxy. The child starts later, with `spawn`.

| `SandboxOrigin` field | Contract                                                                                   |
| --------------------- | ------------------------------------------------------------------------------------------ |
| `origin`              | The origin's name, which keys what the user granted.                                       |
| `url`                 | The Server's URL, as the user gave it.                                                     |
| `app`                 | The directory of the app bundle: its `manifest.json` and the bundle it points to.          |
| `fingerprint`         | The publisher key pinned for the origin. The child refuses a bundle signed by another key. |
| `sessions`            | The name the origin's restored sessions are kept under.                                    |
| `granted`             | The `Capabilities` granted to the origin.                                                  |
| `denied?`             | What the user refused: capability names, and `secrets:<name>`.                             |
| `runtime`             | The result of `sandboxRuntime()`.                                                          |
| `child`               | The path `buildChild()` resolves with.                                                     |
| `mechanism`           | The `mechanism` of `sandboxAvailability()`.                                                |

| `SandboxOptions` field   | Contract                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------------------------ |
| `perform(request)`       | Performs a request the user granted, and resolves with its answer.                                           |
| `env?`                   | The environment whose `XDG_STATE_HOME` holds the restored sessions. Default: `process.env`.                  |
| `ask?(question)`         | Asks the user about a capability that is neither granted nor refused. Without it, such a request is refused. |
| `onChange?(change)`      | Receives each decision the user made, `{ capability, state }`, to remember it.                               |
| `onFailure?(failure)`    | Receives each `ClientFailure` the child reports.                                                             |
| `resolve?`, `onProfile?` | For tests: they map a proxied host to the address dialled, and receive the generated profile.                |

| `Sandbox` member | Contract                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------ |
| `spawn(io)`      | Starts the child on a PTY, and returns its `Pty`. `<TerminalView>` calls it with a `TerminalIo`. |
| `deliver(event)` | Sends the child an event, when its grants let it hear that event.                                |
| `permissions`    | Where each mediated capability stands, as the user decides.                                      |
| `proxy`          | The egress proxy, or `undefined` when the child needs none.                                      |
| `close()`        | Stops the child, the proxy and the connection, and removes the scratch directory.                |

`TerminalIo` is `{ cols, rows, onData, onExit }`: what `<TerminalView>` hands the function that
starts its program. A child still running when the host process exits is killed.

`openSandbox` rejects when it cannot reach the Server, such as `<url>: no port to reach`, or
an `ssh` error for a URL over SSH. It closes what it opened first.

## Replace or wrap the transport

The transport is how the Client reaches the Server: every page render and every Server
Function call goes through it. Inject one with `createApplication({ transport })`, or decorate
the one in use with `createApplication({ wrapTransport })`, without touching the runtime. A
cache, a recorder or a replay is a decorator.

```ts
import { createApplication, TransportError } from "@luciole-sh/core/client";
```

| Option                  | Contract                                                                                   | Default                  |
| ----------------------- | ------------------------------------------------------------------------------------------ | ------------------------ |
| `transport?`            | Replaces the default transport.                                                            | the HTTP transport below |
| `wrapTransport?(inner)` | Receives the transport in use, `transport` or the default one, and returns the one to use. | none                     |

A transport implements three methods:

<Excerpt
  path="packages/core/src/transport.ts"
  find="export interface Transport"
  until="^}"
  tone="wire"
/>

| Method                                               | Contract                                                                                                 |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `render(routeId, params, signal, search?, context?)` | Resolves with the root of the page's Flight model. Suspense content and async iterables stream after it. |
| `call(actionId, args, signal?, context?)`            | Resolves with the Server Function's value.                                                               |
| `setToken(token?)`                                   | Sets the token sent with each later request, or removes it.                                              |

`context` carries the request's `cause`, which the events report. Its `onTags` receives the
`"use cache"` tags the page read, once its render has ended.

### The default HTTP transport

When `transport` is absent, `createApplication` builds the HTTP transport from these options.
The HTTP transport itself is not exported.

| Option       | Contract                                                                                           | Default            |
| ------------ | -------------------------------------------------------------------------------------------------- | ------------------ |
| `url`        | The Server's URL.                                                                                  | required           |
| `buildId`    | Sent with each request. A Server of another build answers 409.                                     | required           |
| `token?`     | The token, sent as `Authorization: Bearer <token>`.                                                | none               |
| `timeoutMs?` | How long to wait for the root of an answer, in milliseconds. The stream behind it may last longer. | `10000`            |
| `latencyMs?` | A simulated round-trip latency added to each request, in milliseconds.                             | `0`                |
| `network?`   | Simulated jitter, slow chunks and faults ([latency and faults](/docs/guides/latency-and-faults/)). | none               |
| `fetch?`     | The function that sends each request.                                                              | the global `fetch` |

The HTTP transport also hands the app the paths and tags a Server Function invalidated, and
reports each request's events to `useApplication().onEvent`.

`createApplication` throws `latencyMs must be a finite non-negative number` for a negative or
infinite `latencyMs`. The same message names `jitterMs` or `chunkDelayMs` of `network`.

A failed request rejects with a `TransportError`, whose `outcome` says whether the Server ran
anything:

| What happened                                              | Error                                                      | `outcome`  |
| ---------------------------------------------------------- | ---------------------------------------------------------- | ---------- |
| No connection, or the request was cancelled before it left | `TransportError`                                           | `not-sent` |
| The Server answered 409                                    | `BuildMismatch`, with the Server's message                 | `rejected` |
| The Server answered 401                                    | `AuthenticationRequired`, with `loginPath` from the Server | `rejected` |
| The Server answered another 4xx                            | `TransportError`: `HTTP <status>: <body>`                  | `rejected` |
| The Server answered 5xx                                    | `TransportError`: `HTTP <status>: <body>`                  | `unknown`  |
| The timeout ended, or the response was lost or cut         | `TransportError`                                           | `unknown`  |
