the Client reloads only the routes that read that tag.

## Mark a function or a module as cached

- **A module**: `"use cache"` at the top caches every exported function. The module exports
  only `export async function` declarations, and types.
- **A function**: `"use cache"` as the first statement of an `export async function`
  declared at the module's top level.

The build refuses the following, and names the file and line:

- a closure, a method or an arrow function
- a function that is not exported, or not async
- a default export, such as a page component
- an exported value or a re-export in a `"use cache"` module
- `"use cache"` in a `"use server"` or `"use client"` module
- a `"use cache"` module that the Client's code imports

Cache the functions a Server Function calls, not the Server Function itself. A Server
Function receives its arguments from the Client.

## When two calls share a result

Two calls share an entry when they run under the same build, call the same function and pass
equal arguments. **A new build never reads another build's entries.** Arguments follow the
rules of Server Function arguments, so `Date`, `Map`, `Set`, `BigInt` and `undefined` keep
their type.

- Each caller receives its own copy. Changing it leaves the entry as it was.
- Concurrent calls with the same arguments share one computation.
- An exception is never cached.

The cache stores data, not trees. Arguments and results cannot be async iterables,
`ReadableStream`, React elements, Client functions or `Blob`.

## Label and age a result with `cacheTag` and `cacheLife`

Both work only while a `"use cache"` function runs.

`cacheTag(...tags)` labels the result. A tag holds 1 to 256 visible ASCII characters, without
commas, and a result holds at most 64 tags. Encode free identifiers, as `server/tags.ts` does
with `encodeURIComponent`.

`cacheLife(profile | { revalidate?, expire? })` sets the result's lifetime, in **seconds**.
When a function calls `cacheLife` several times, the shortest value of each field wins.

| Profile   | `revalidate` | `expire`  |
| --------- | ------------ | --------- |
| `default` | 900          | never     |
| `seconds` | 1            | 60        |
| `minutes` | 60           | 3,600     |
| `hours`   | 3,600        | 86,400    |
| `days`    | 86,400       | 604,800   |
| `weeks`   | 604,800      | 2,592,000 |
| `max`     | 2,592,000    | never     |

The age of an entry decides what a call gets:

| Age of the entry              | Result                                                                  |
| ----------------------------- | ----------------------------------------------------------------------- |
| below `revalidate`            | `hit`: the stored value                                                 |
| from `revalidate` to `expire` | `stale`: the stored value now, and a new one computed in the background |
| `expire` or more              | `miss`: the caller waits for the computation                            |

If the background computation of a `stale` entry fails, the old value stays until `expire`.
A cached function that calls another inherits its tags and its shortest lifetime.

<Note kind="warning">
  `getSession()` and `getOptionalSession()` **throw** inside a cached function and anything it
  calls. Every caller with the same arguments receives the same result, so it cannot depend on who
  signed in. Pass the identity as an argument, as Notes does with `noteOf(getSession().userId,
  params.id)`.
</Note>

## Where entries live

| Handler                                     | Scope                                                                       |
| ------------------------------------------- | --------------------------------------------------------------------------- |
| `memoryCache({ maxEntries = 1000 })`        | The default. This process only. The least recently used entry leaves first. |
| `sqliteCache({ path, maxEntries = 10000 })` | Survives restarts. The Server processes of one machine share it.            |

A memory cache is empty after every restart, so after every rebuild of `bun run dev`. To
pick a handler, export it by default from an optional `server/cache.ts`:

```ts
// server/cache.ts
import { sqliteCache } from "@luciole-sh/core/server";
export default sqliteCache({ path: process.env.CACHE_DB ?? "cache.sqlite" });
```

A custom handler implements `get`, `set` and `invalidateTags`. Its `invalidateTags` must
remove the entries before it resolves, since the Client reads again right after.

## How a tag travels from a read to a reload

Each render records the tags of the cached reads it made, in async Server Components under
`Suspense` too. A hit counts as much as a miss. The tags reach the Client after the page.

When a Server Function invalidates a tag, the Server purges its entries before it answers.
The answer names the tag, and the Client reloads two kinds of routes:

- the routes whose page read the tag
- the routes whose tags it does not know yet, such as a page still loading

With `staleTime` 0, the default, TanStack reloads every **mounted** route on any
invalidation. The choice by tag matters for routes in the router's cache, and for pages that
declare a `staleTime`.

## Show a page without a request with `staleTime`

```ts
export const staleTime = 30; // seconds; a literal or a product (5 * 60)
```

For that long, coming back to the page shows its cached tree **without a request**. Without
`staleTime`, the cached tree shows and then reloads. An invalidation by path or by tag, and
`refresh()`, reload the page before the time is up.

## Invalidate a tag outside a Server Function

`invalidate({ tag })` also works outside any Server Function:

- in a background task or a webhook
- during a render
- from the DevTools

It then purges **the Server cache only**. No answer goes to a Client, so no Client reloads.
Each Client reads fresh data at its next render of the route. `invalidate(path)` outside a
Server Function throws, since no Client could receive it.

## What the cache does not do

- It does not cache React trees, such as components or pages.
- The Client cannot invalidate a tag: `useApplication().invalidate` takes paths.
- Concurrent calls share a computation within one process only. A shared SQLite cache shares
  entries, not computations.
