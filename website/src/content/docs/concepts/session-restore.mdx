The Client plays the browser's part, so it keeps what a browser keeps of a session: **the
history and, for each entry, the text typed into its named fields, which one had the focus
and how far its named scroll boxes were scrolled**. Nothing else. Page data
comes back from the Server by navigating; the bearer token stays with the app; a field
without a `name` is never written (a PIN, a password).

## Naming a field

`<Input>` and `<Textarea>` from `@luciole-sh/core/client` are OpenTUI's `input` and `textarea`,
controlled. A `name` makes their text restorable:

<Excerpt
  path="examples/chat/components/Chat.tsx"
  find="<Textarea"
  after='id="composer"'
  until="/>"
  mark={['name="chat/prompt"']}
  tone="client"
/>

`Textarea` makes OpenTUI's `textarea` controlled, which it is not by itself: `value` in,
`onChange` out, like the input. A value set from outside replaces the content and puts the
cursor at the end.

## A field of your own

A field that is neither (an editor, a canvas) gets the same keeping from
`useRestoredField(name, value, onChange)`: the kept text comes back once through
`onChange` when the field mounts, and the function it returns takes every text the user
types. Notes keeps its WYSIWYG editor's Markdown this way:

  until=";"
  mark={['"note/text"']}
  tone="client"
/>

## The focus and the scroll boxes

A browser gives the focus back to the field the user left and scrolls the page to where it
was. A terminal app decides its focus itself (`focused={…}`) and scrolls boxes, not a
page, so the two are opt-in, by name:

- `useRestoredFocus(names)` is the app's focus state, kept per entry: `[focus, setFocus]`,
  the first name until the user moves it. A kept name that is no longer among `names` (a
  field removed since) gives the first one.
- `<ScrollBox name>` is OpenTUI's `scrollbox` whose position is kept per entry. The kept
  position waits for the content to be tall enough (a list the page loads, a live feed),
  for a moment after mounting; scrolling by the user in the meantime wins.

## What comes back

| When                                                   | What comes back                                                   |
| ------------------------------------------------------ | ----------------------------------------------------------------- |
| Back to a history entry (`u`, back)                    | That entry's named fields, focus and scroll positions             |
| A rebuild under `luciole dev`                          | The page, the history, the entries' state and the bearer (memory) |
| Crash, `kill -9`, closed terminal, SSH cut (SIGHUP)    | The page, the history and the entries' state, at the next launch  |
| SIGTERM (machine shutdown), desktop window included    | The page, the history and the entries' state, at the next launch  |
| <kbd>Ctrl+C</kbd> or `app.quit()`: quitting on purpose | Nothing: the session is deleted, like a browser closed on purpose |
| Desktop window closed (SIGHUP under `LUCIOLE_DESKTOP`) | Nothing: closing the window quits the app                         |

- **Per history entry**, as in a browser: opening the same page again from a link creates a
  new, empty entry. Keeping text per document whatever the path (Notes' and Forge's Drafts)
  is the app's policy.
- **A field belongs to the entry where it was mounted**: a field in a persistent layout keeps
  writing to the entry where it appeared.
- **Restoring is retyping**: on mount, a field whose entry holds text calls `onInput` (or
  `onChange`) once with it. The app's state, or its form library's, receives it the way it
  receives typing, as unsaved work. Only typed text is kept; a value the app sets (a reset)
  only follows text already kept.

<Note kind="warning">
  Anything held only in memory, Drafts included, is lost on every exit and on every rebuild. There
  is no Fast Refresh.
</Note>

## Sending without sending twice

A group gathers the fields named `group/field`. `useRestoredFields("group").submit(action)`
forgets their text **before** the request leaves, on disk too. A Client killed while sending
does not offer the text again. `tests/restore-submit-kill.test.ts` kills one with SIGKILL as
its save leaves, then checks that the next Client starts without the text.

The text is kept again, unless the user typed something newer meanwhile, when:

- the outcome proves nothing ran (`not-sent`, `rejected`)
- `failed(result)` says the Server refused it

`clear()` forgets the text on demand.

## With a form library

The framework neither validates nor sends forms. Libraries that drive a field by value and
callback work as they are, through their "React Native" path. TanStack Form is the one the
examples follow (Forge's new pull request form, `components/NewPullForm.tsx`): fields go
through `useField` rather than `<form.Field>`, and a key binding calls `form.handleSubmit()`,
since a terminal has no `<form>`. React Hook Form works with `useController`; Formik with
`useFormik` and `handleChange("field")`, never its `<Form>` and `<Field>` components, which
render HTML.

## Storage

- One file per Client (like a tab), mode `0600`, in
  `$XDG_STATE_HOME/luciole/<app>/sessions/` (`~/.local/state/…`), written 200 ms after the
  last change and before exiting on a signal.
- After a crash, the next Client takes over the most recent session left by a dead Client
  for the same Server address, never one of a living Client.
- At most 50 entries; a field longer than 100,000 characters is not kept; an orphaned
  session is deleted after 7 days. **The text is not encrypted.**
- Replacing a bearer (`setToken`, a sign-out or another account) forgets every field's text
  (the focus and scroll positions stay: they hold nothing the user typed); a
  Client's first sign-in keeps them, so text restored after a crash survives the sign-in it
  asks for. Another account that signs in first after a crash finds the previous one's text: the
  session belongs to the system user, like a browser profile.
