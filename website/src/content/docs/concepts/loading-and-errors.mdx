A navigation shows a screen at once, drawn by the Client, while the page travels: the
loading screen replaces **only** the page, and the layouts around it stay mounted.

## `loading.tsx`

A `loading.tsx` becomes the pending screen of every page below its directory; a page takes
the nearest one among its parents. It receives the destination's `params`. Without one,
the framework shows "Connecting…" before the first answer, then "Loading…".

The loading screen and the page it stands for should share their layout rules, or the page
jumps when it arrives. Notes draws both with `components/NoteFrame.tsx`: same frame, a
status line, the title on one line, the note below; the title is already known, from the
list the layout holds. The framework cannot know the size of a Server page it has not
received yet: that stability is the app's contract. An animation should change colours or constant-width glyphs only; Notes pulses
the skeleton's opacity with OpenTUI's `useTimeline` and stops it on unmount.

## `error.tsx`

An `error.tsx`, inherited the same way, replaces the page when its loading or rendering
fails. It receives `{ error, path, params, retry }`: `error` is a `TransportError` with its
`outcome`, or a Server render error (opaque in production); `retry()` loads the page again.
Without one, the message is shown.

<Excerpt path="examples/notes/app/error.tsx" tone="client" />

The page's error screen, yours or the default one, also emits a `failure` event (`path`,
`message`) through `useApplication().onEvent`. A Client started with an IPC channel, by
`luciole dev` or a sandbox host, forwards it to its parent, which learns which page failed and
why ([`luciole/dev`](/docs/reference/api/#supervising-an-app-lucioledev)). A page that calls
`notFound()` emits none: a missing page is an answer, not a failure.

A failed navigation shows `error.tsx` in the page's place with the layouts still mounted.
A failed **refresh** keeps the current tree mounted instead, and exposes the error in
`useConnection().error`.

## `not-found.tsx`

A page calls `notFound(what?)` from `luciole/server` to end its render with the nearest
`not-found.tsx`, which receives `{ path, params, what }`. `app/not-found.tsx` also answers a
URL that no page matches. The status stays "Connected": a missing page is an answer, not an
outage.

## The connection, in the app's chrome

The framework draws no header or footer. `useConnection()` gives the chrome what it needs:
`status`, `error`, `buildError` (a failed rebuild under `luciole dev`), `refresh`, and
`activity`, one of `connect`, `navigate`, `refresh` or `idle`. Notes has no toolbar: it
says all of it on the line above the note's title, the one its save uses, one message at a
time. A lost connection comes first, then the page's own words, then what the router is
doing; each waits a moment before it speaks, so that a line which says nothing while all
goes well does not flash after every save:

## Cancelling and refreshing

- <kbd>Esc</kbd> during a navigation, or `useApplication().cancel()` (Notes' **Cancel** button),
  goes back to the last resolved route locally, without reloading it.
- `refresh()` reloads the destination in progress or the mounted route. During a refresh
  the tree stays mounted (`activity === "refresh"`): fields keep their focus and text. The
  examples bind it to <kbd>Ctrl+R</kbd>, and Notes to a **Reconnect** button while offline:
  the key and the control are the app's choice.
- A `401` redirects to the app's `unauthorizedPath`, if it declares one, without rendering
  protected content ([authentication](/docs/concepts/authentication/)).
- A `409` (another build) is refused before decoding and purges the router's cache.

<Note>
  Loading screens are Client Components on purpose: they must show without the network. A loading
  screen that needs data from the Server is a page, and would wait for it.
</Note>
