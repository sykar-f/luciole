Open an app that someone else wrote, and choose what its code may touch on your machine. You
need this guide when the app comes from a URL or from a package that is not signed.

The app's Client Components run with the rights of the process that runs them. The generic
Client, the `luciole` command that opens an app by URL, sets the limits per **origin**. An
origin is one of:

- the Server's URL as you typed it: scheme, host and port, not a tunnel's local address
- an installed package
- a local command

## Choose a mode

| Mode      | Where the app runs                                  | Isolation                                       | For                                            |
| --------- | --------------------------------------------------- | ----------------------------------------------- | ---------------------------------------------- |
| `inline`  | inside the Client's process, in the same React tree | none                                            | code you trust: yours, installed, signed       |
| `process` | a child process on its own PTY, no sandbox          | crashes only                                    | a local multiplexer: shells, vim, luciole apps |
| `sandbox` | a child process under the OS sandbox                | crashes, and the granted capabilities, enforced | a remote URL, an unsigned package              |

You choose the mode, with a flag or once per origin. The app cannot choose it.

- `process` adds **no** security layer. It is tmux, not a browser.
- `inline` is full trust: the declared capabilities are not enforced. The generic Client says so
  before it opens the app.
- `sandbox` is the only mode where something checks the app's reads, writes and requests.

## Open an app by URL

```sh
luciole https://notes.example.com
```

1. The generic Client fetches `GET /manifest` and checks the publisher's signature.
2. On first use, it **pins the publisher's key** for that origin, like SSH's `known_hosts`. It
   shows the key's fingerprint and asks you.
3. It reads the bundle from its cache by hash, or downloads `GET /bundle/<sha256>`. Either way,
   it checks the bundle's SHA-256.
4. Before anything runs, the **capabilities screen** lists the Server's route and each granted
   capability with who enforces it. A "refused" line names what this system cannot enforce.

A different key on a later visit is refused. When the publisher confirms a new key out of band,
pin it with `luciole trust <url> <SHA256:…>`.

<details>
<summary>What the manifest binds, and what the signature covers</summary>

The manifest binds the build ID, the bundle's SHA-256 and size, the runtime ABI key, the Node
built-ins the bundle needs, and the publisher's Ed25519 public key. The signature covers a
canonical encoding of these fields, not the JSON as received. The generic Client also compares
the ABI key with its own before it reads the bundle.

</details>

A publisher signs with `luciole keys generate`, once, then `luciole build --sign-bundle`. This
key has nothing to do with Apple's Developer ID.

The default mode for a URL depends on the system:

- `sandbox` on macOS
- `sandbox` on Linux, where the sandbox also confines the network: user namespaces or bubblewrap
- elsewhere, nothing opens without an explicit `--sandbox` or `--inline`, remembered per origin

## Declare and grant capabilities

An app declares what it may do in the `luciole.capabilities` field of its `package.json`. You
can read the field before anything runs. The build copies it into the signed manifest. The
build also warns about the Node built-ins the Client bundle uses without declaring them.

```json
{
  "luciole": {
    "capabilities": {
      "fs": { "read": ["/home/me/notes"] },
      "net": ["api.example.com"],
      "openUrl": true
    }
  }
}
```

The table gives each key with the flag that grants the same thing. `fs.read` is the `read` key
of `fs`, and `clipboard.read` is the `read` key of `clipboard`. Every key defaults to nothing.

<Note kind="warning">
  The runtime ignores a key that is not in this table, without a warning. A misspelled key, such as
  `open-url` in place of `openUrl`, grants nothing.
</Note>

| Key               | Flag                        | What it grants                                                       |
| ----------------- | --------------------------- | -------------------------------------------------------------------- |
| `fs.read`         | `--allow-read=<paths>`      | reading files under absolute paths                                   |
| `fs.write`        | `--allow-write=<paths>`     | writing files under absolute paths                                   |
| `net`             | `--allow-net=<hosts>`       | outgoing connections to `host`, `*.host` or `host:port`, or `*`      |
| `exec`            | `--allow-exec[=<binaries>]` | running programs: `true` for any, or a list of absolute binary paths |
| `pty`             | `--allow-pty`               | pseudo-terminals                                                     |
| `clipboard.read`  | `--allow-clipboard-read`    | reading the clipboard                                                |
| `clipboard.write` | `--allow-clipboard-write`   | writing the clipboard                                                |
| `notify`          | `--allow-notify`            | desktop notifications                                                |
| `openUrl`         | `--allow-open-url`          | opening an http(s) URL                                               |
| `secrets`         | `--allow-secrets=<names>`   | the keychain entries of the origin, by name                          |
| `inputGlobal`     | `--allow-input-global`      | keys typed in other tabs                                             |
| `tabsMessage`     | `--allow-tabs-message`      | messages between tabs                                                |

You accept the capabilities an app declares once per origin. Pass the flags when you open the
URL to add to them. `luciole` remembers everything in the origin's `origin.json`.

**Declaring is not enforcing.** Only the `sandbox` mode enforces capabilities. The capabilities
screen shows a capability as enforced only if something enforces it.

## Who enforces what

| Capability                                    | macOS                                                       | Linux                                                                        |
| --------------------------------------------- | ----------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `fs.read`, `fs.write`                         | the OS: Seatbelt, by path                                   | Landlock, plus bubblewrap's mounts under bubblewrap                          |
| `net` by host                                 | a proxy the host holds. The OS limits the child to its port | the proxy, in a network namespace. Refused with Landlock alone               |
| `net: *`                                      | the OS                                                      | the OS                                                                       |
| `exec`                                        | the OS                                                      | Landlock. Refused under bubblewrap without Landlock                          |
| `pty`                                         | **refused**: the rule would open the user's other terminals | a private devpts, with namespaces or bubblewrap. Refused with Landlock alone |
| `clipboard.*`, `notify`, `openUrl`, `secrets` | the host. The OS blocks the direct way                      | the host. seccomp refuses Unix sockets: D-Bus, Wayland, X11                  |
| `inputGlobal`, `tabsMessage`                  | the host, over IPC                                          | the host, over IPC                                                           |

The capabilities the host checks reach it through `host`, from `@luciole-sh/core/client`:

```ts
await host.clipboard.write(text);
await host.notify({ title: "Saved", body: "notes/a.md" });
await host.openUrl("https://luciole.sh");
const token = await host.secret("api-token");
```

Each call travels over an inherited IPC channel, and the host validates each message with Zod.
The host checks the capability, asks the user if it is undecided, then acts. An OSC 52 sequence
that a sandboxed app writes never reaches the clipboard: the host checks only the `host` path.

### Which sandbox runs on each system

- **macOS**: Seatbelt, through `sandbox-exec`. The profile is generated from the capabilities,
  on `deny default`. Without `/usr/bin/sandbox-exec`, the mode is refused.
- **Linux**: `luciole-sandbox`, a native launcher in Rust that ships compiled with luciole. It
  applies namespaces, Landlock and seccomp just before it runs the child.

On Linux, `luciole-sandbox` picks the strongest mechanism the system allows, in this order:

1. its own **user namespaces**
2. **bubblewrap**, where AppArmor refuses namespaces to the launcher, as on Ubuntu 23.10 and
   later
3. **Landlock alone**, which does not confine the network by host and is never the default

With none of them, the mode is refused, and the error gives the reason.

<Note kind="warning">
  Landlock alone confines files, programs and signals, but not the network by host. A URL opens with
  it only with an explicit `--sandbox`, and a `net` by host is refused. The capabilities screen says
  that the network is **not** confined.
</Note>

## Confine the Server of an untrusted app

The modes above confine a Client. A host that also runs the **Server** of an app it does not
trust can confine that Server too, on macOS. The studio example does this for its preview: a
coding agent writes the app's pages and Server Functions while you use it.

`confineServer`, from `@luciole-sh/core/sandbox`, starts the Server under the same generated
Seatbelt profile. The Server gets:

- no terminal
- one loopback port, which the host picks, to listen on
- reads limited to its build
- writes limited to its data directory
- `net` by host, through the host's egress proxy

The host passes the `command` and `env` that `confineServer` returns to `startAppServer`, from
[`@luciole-sh/core/dev`](/docs/reference/api/#supervising-an-app-luciole-shcoredev).

On Linux, `confineServer` refuses to start, with the reason. Under `luciole-sandbox`, the Server
would listen inside its own network namespace. The host would then need a reverse relay to
reach it, and that relay is not built.

## Run other apps inside your app

The same modes exist inside an app:

- `<Embed>` runs another luciole app `inline`, in a pane.
- `<Terminal>` runs a local program in `process` mode.

See [terminals and panes](/docs/guides/terminals-and-panes/).

## Check what an origin was granted

The capabilities screen shows, before the app runs, what it is granted and who enforces each
capability. Later, read the origin's `origin.json`, under
`~/.local/state/luciole/origins/<sha256 of the origin>/`, or under `$XDG_STATE_HOME` when it is
set. It holds the pinned key, the mode you
chose, the capabilities the app declared and those you granted.

## What is not covered yet

- The pinning is per origin. A Server that changes host or port is a new origin: a new question
  and a new pinned key.
- Key rotation is not designed yet.
- A compiled binary does not embed the app bundle. Its Server answers `404` to `/manifest`, so
  you cannot open it by URL.

See also the [CLI reference](/docs/reference/cli/) for `luciole trust` and `luciole keys`, and
[opening an app](/docs/guides/opening-an-app/) for the other ways to reach a Server.
