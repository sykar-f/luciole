Summary: `newSlave` (packages/luciole/src/vt/pty.ts) no longer scans `/dev` against a time budget. It asks each descriptor opened since `before` for its own path (`realpathSync("/dev/fd/<n>")`: F_GETPATH on macOS, `/proc/self/fd/<n>` symlink on Linux) and keeps the one matching `/dev/ttysNNN` or `/dev/pts/N`; the master (`/dev/ptmx`) never matches. `SCAN_ATTEMPTS`, `SCAN_PAUSE_MS`, `slaves()` and `Bun.sleepSync` are gone: nothing waits, so no load can exhaust a budget. A failure left (descriptor not resolvable) is deterministic, not a function of load. New tests/pty-slave.test.ts opens 200 PTYs in a row and checks every slave path is found, is a character device, and is distinct.
Deviations from the brief: none. The Linux run was NOT possible (see Risks).

Risks:
- Linux unverified: no Docker engine on this host (`docker: command not found`), so `test:linux` / the container scripts could not run. The Linux path rests on `/dev/fd` -> `/proc/self/fd` and its per-fd symlinks to `/dev/pts/N`, which `realpath` follows; please run `bun run test:linux` where Docker exists.
- Why the device can be missing from `/dev` at first: NOT reproduced, so not proven. Measured here (macOS, load 27): 200 PTYs in a row, the descriptor's path always existed in `/dev` and its `rdev` matched the descriptor's (0 missing, 0 mismatch), and the old scan also found them at a calm load. The failure was seen only at load ~440. What the evidence supports: the old code resolved the path indirectly, by matching `rdev` against a listing of `/dev` (readdir then stat per entry), while other sessions create and delete slave nodes and macOS reuses minor numbers; any listing taken in that window can miss or mis-key an entry, and a fixed budget makes it a failure. The descriptor path does not depend on the listing. I make no claim about the kernel's node-creation timing.
- A runtime where the slave path is not under /dev/ttysN or /dev/pts/N (a chroot or container with another devpts mount path) now throws; the old scan had the same limit.
Merge notes: touches only vt/pty.ts and the new tests/pty-slave.test.ts; the exit cleanup (live registry, killAll) is untouched.
