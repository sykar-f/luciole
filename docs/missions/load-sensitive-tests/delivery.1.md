**lifetime — "pings follow a Server going away and coming back"**
- Root cause: `keepAlive` (`packages/luciole/src/connect.ts`, the `AbortSignal.timeout(pingMs)` of `ping`) gave a ping only as long to be answered as the interval between pings, 100 ms in the test. On a loaded host an answer later than that is an abort, reported as "Server unreachable": a flap on a Server that never left. The first answer also only set a silent baseline (`before !== undefined`), so a first ping aborted that way started the watcher at "unreachable", and the test's `Bun.sleep(300)` (`tests/lifetime.test.ts:152` on base) was a guess that the baseline was set before the Server stopped.
- Reproduction: freezing the Server with SIGSTOP for 350 ms around `connect` made the base test fail deterministically with `seen = [true,false,true]`; with the fix it gives `[false,true]` (3/3).
- Fix (production, `connect.ts`, because the root cause is there): the ping's answer budget has its own variable `LUCIOLE_PING_TIMEOUT_MS`, defaulting to the interval, so behaviour is unchanged unless set (documented in `reference/environment.mdx`); and the Client starts as reachable, as its own comment said, so a first ping that fails is reported instead of lost. The test asks for quick pings (100 ms) but an answer budget it never depends on: a Server that is gone fails at once (connection refused), only a slow one would use the time. The sleep is gone; nothing waits on a duration any more.

**notes — "a slow save is said to be slow, then unconfirmed…"**
- Root cause: `tests/notes.test.tsx` base `await eventually(() => status(ui) === "Still saving…", QUIET_MS * 2)`. That status exists only between the editor's 3 s quiet period and the Client's 3.5 s request timeout (`timeoutMs: 3500`): a 500 ms window the poll had to land in. A host that starves the poll for half a second sees "Disconnected" first and never the window. The following `"○ Disconnected…"` assertion had the same shape: it holds only until the first automatic retry (RETRY_FIRST_MS = 1 s after the unknown outcome) finds the Server up and the connection back.
- Reproduction: stalling the test process 1.2 s every 3 s (SIGSTOP/SIGCONT, Server child running): base test failed 1 run in 8; the new test passed 10/10 plus 5/5 earlier.
- Fix (test only): `slowSaves()`, a `wrapTransport` decorator, makes the Server slow by the test's hand: the save and its lookup (`#saveNote`, `#getOperation`) reach the real Server only when the test calls `land()`, and the first save is given up on with a `TransportError` (outcome `unknown`, as the transport does at its timeout) when the test calls `timeOut()`. Every state is held until looked at; no deadline orders the steps. Asserts are unchanged (slow, then unconfirmed + Reconnect, Ctrl+S looks it up, settles with the baseline). The `QUIET_MS` waits that remain are the real 3 s of the editor, awaited as a hang guard on a persistent state, not a window. The transport's own timeout → `unknown` outcome stays covered by `tests/http-transport.test.ts` (`timeoutMs: 20`), which this test no longer re-proves with a 3.5 s timer.
